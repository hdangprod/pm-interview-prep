## Findings and decisions

- **Reusable:** concise sourced company research; real-answer evidence; raw/polished separation; existing case IDs and scenarios; simple English phrases.
- **Too much daily overhead:** mandatory MASTER_STATE reading, per-answer logs, score updates and detailed minute allocations. Removed these obligations from active instructions/navigation.
- **Redundant for learning:** state, plan, scorecards and case queues repeated next-action information. Kept them as explicitly historical reference, outside the primary learner path.
- **Missing:** root README for GitHub, a learner roadmap, compact review, standalone teaching notes and a portable Gemini prompt.
- **Unsuitable existing case format:** intertwined questions, scoring instructions and progress status. Reused the questions/IDs in learner-facing CASES files; original records remain optional history.
- **Preservation:** research, stories, original raw sources and practice answers kept in place. Archived the old README protocol before replacing it. No personal evidence embellished.
- **Missing evidence:** no detailed TDCX/FPT Software incident, CV or verified PRJ226 architecture/outcome. Employer names in the new request do not establish achievements.
- **Source limits:** prior Ybox retrieval returned 403; program details have employer LinkedIn/UEH corroboration. Interview times and exact BAC mechanics remain unknown.

## New structure

Root README opens the existing pm-interview-bootcamp folder through direct learning links. The learning layer lives there to avoid moving evidence or duplicating study kits.

ROADMAP is the single active study schedule. QUICK_REVIEW is the fast recall path. study/ contains five teaching notes, with section jumps for MCP and order-decline diagnosis. Gemini needs only the short prompt plus the relevant excerpt/case.

No software, automation, dashboards or required reports added.
