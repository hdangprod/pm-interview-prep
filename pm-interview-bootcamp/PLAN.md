## Case and simulation design

Katalon final: 5-minute background, 15-minute discovery case, 15-minute AI/agents/MCP and QA probing, 10-minute spec/evaluation, 10-minute behavioral/director pressure, 5-minute feedback. Ask sequentially.
ShopeeFood final: 5-minute business brief, 20-minute diagnosis/data interaction, 10-minute recommendation, 15-minute stakeholder/constraint probes, 10-minute feedback. Practice group collaboration only if format confirmed or time remains.
These durations are training design, not claims about actual interview timing.

## Adaptive branches

- After baselines, allocate roughly 60% of flexible practice to the weaker track, 25% to shared evidence/communication, 15% to maintaining the stronger track; retain both final mocks.
- If decomposition or metrics ≤4: next block is one smaller diagnosis/data drill, then an unseen retry.
- If AI/MCP vocabulary exceeds practical explanation: trace one actual tool/action and failure; do not add terminology reading.
- If marketplace reasoning ignores a stakeholder: reconstruct one order lifecycle before adding another growth case.
- If product reasoning ≥7 but delivery ≤5: compress the same idea to 60–90 seconds and retest; avoid adding content.
- If story lacks factual support: extract a specific incident or use another story. Never fill gaps with plausible numbers.
- If two unaided attempts score ≥7 in a skill: stop repetitive drilling; transfer to a different setting.
- If only 90 minutes/day: retain 35-minute highest-risk case, 20-minute probe/retry, 20-minute alternate-track maintenance, 15-minute story/English retrieval. On Sep 15, use two 40-minute mocks plus 10-minute triage.
- If availability is greater: add unseen pressure tests or observed product walkthroughs, not a broad syllabus.
- If interviews shift: recompute available hours and preserve the highest-risk practice and final simulations.

## Deliberately deprioritized

No broad PM courses, long videos, exhaustive competitor matrices, market-share trivia, sophisticated vocabulary, framework memorization, advanced SQL puzzles, model-training math, production MCP implementation, or new PRJ226 feature builds just to sound impressive.
Use ≤15 minutes of new research per day unless a factual gap blocks the next drill.
Keep a small targeted product walkthrough if access is already available; do not make hands-on access a prerequisite for diagnosis.
